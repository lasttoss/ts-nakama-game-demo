Runtime · ts-nakama-game-demo

What the host registers once, and what happens on the first login

A Nakama plugin written in TypeScript: one module, three registrations, and a hook that seeds a new player exactly once — so no RPC has to know what a new player looks like.

device login · after-authenticate hook guarded by a hasInit flag · server-authoritative per-player match · inventory / shop / energy in Nakama storage collections · four RPCs
Why the hook, not each RPC

If every entry point had to create a missing wallet, every entry point would need to know what a new player looks like — and one of them would eventually forget. The hook is the single place a player is born.

Why the guard is explicit

The hook fires on every authenticate, so the seeding it does has to be safe to run again. A named flag says that out loud, and the test that reads it back is what keeps it true.

Where the state lives

Inventory, shop and energy live in storage collections rather than in the node's memory, so a restart is not a reset. That is the same reason the match, not the client, owns the state.
